# FlowLab Weather Intelligence Workflow

This document maps the research architecture to the GitHub Actions workflow in `.github/workflows/weather-intelligence.yml`.

## Scientific scope

FlowLab Weather Intelligence is an inspectable research prototype. It combines a beta-plane rotating shallow-water model with simplified thermodynamics, moisture, precipitation, terrain forcing, sparse observations, data assimilation, ensemble forecasting, a learned diagnostic emulator, verification, and bounded parameter learning.

It is not an operational numerical weather prediction system and does not claim AGI.

## Process 04 — Physics core

Module: `weather_agent/advanced.py`

Mechanisms:
- rotating shallow-water dynamics
- nonlinear horizontal advection
- pressure/geopotential gradients
- viscosity/diffusion
- beta-plane Coriolis variation
- terrain-induced geopotential forcing and drag

Artifact: `04-physics.json`

## Process 05 — Thermodynamics, moisture and precipitation

Mechanisms:
- temperature advection and diffusion
- humidity advection and diffusion
- saturation humidity approximation
- condensation
- latent heating
- rain production and fallout
- orographic lifting

Artifact: `05-moisture.json`

## Process 06 — Terrain and Coriolis

The workflow reports terrain range and latitude-dependent Coriolis range so these forcings remain visible and testable.

Artifact: `06-terrain-coriolis.json`

## Process 07 — Observations

Module: `weather_agent/assimilation.py`

The pipeline samples sparse noisy station-like observations from a held-out reference state. Observation-error assumptions are stored explicitly in the artifact.

Artifact: `07-observations.json`

## Process 08 — Data assimilation

A localized Gaussian nudging analysis spreads observation-minus-background innovations around each station. The workflow records RMSE before and after assimilation.

Artifact: `08-assimilation.json`

## Process 09 — Ensemble forecast

Module: `weather_agent/ensemble.py`

The model creates perturbed initial-condition members, integrates each member, computes an ensemble mean and spread, and verifies the ensemble mean against held-out synthetic truth.

Artifact: `09-ensemble.json`

## Process 10 — Learned emulator

Module: `weather_agent/emulator.py`

A small ridge-regression surrogate learns one-step evolution of summary diagnostics generated by the physical model. This demonstrates the learned-emulator layer without pretending to replace a full gridded NWP model.

Artifact: `10-emulator.json`

## Process 11 — Forecast verification

The system compares a background forecast and an analysis forecast against a held-out synthetic truth, producing field RMSE for height, winds, temperature, humidity and rain.

Artifact: `11-verification.json`

## Process 12 — Learning from error

The pipeline evaluates several assimilation gains on validation error and selects the best-performing candidate. This is deliberately bounded parameter learning, not unconstrained code self-modification.

Artifact: `12-learning.json`

## Process 13 — Complete snapshot

The pipeline runs every stage and stores the combined machine-readable result.

Artifact: `13-complete-pipeline.json`

## Run locally

```bash
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements-weather.txt
pytest -q
python -m weather_agent.pipeline --stage all --out artifacts/local-complete.json
```

Run a single stage:

```bash
python -m weather_agent.pipeline --stage assimilation --out artifacts/assimilation.json
```

## GitHub Actions experiment ledger

Every stage writes its JSON output into `$GITHUB_STEP_SUMMARY`. At the end of the job, all stage files are uploaded under the `weather-intelligence-results` artifact for 30 days.

The rule for future development is simple: every new scientific mechanism should add (1) an explicit model assumption, (2) a test, (3) a verification metric, and (4) a named GitHub Actions stage.
